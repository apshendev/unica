# Выпуск гейтится потребителями OpenCode минимальной версии

**Решение.** Теговый выпуск форка проверяется реальными потребителями
npm-пакета: после публикации job'ы ставят изолированный OpenCode ровно
версии 1.18.22 — заявленный пол поддержки, подключают
`@apshendev/unica-opencode@<версия выпуска>` из реестра и проверяют два
наблюдаемых факта: `opencode debug skill` перечисляет все упакованные
скиллы, `opencode mcp list` показывает `unica` подключённой через упакованный
bootstrap. Windows x64 блокирует выпуск; Linux x64 — best-effort с
`continue-on-error`: видит, но не блокирует. macOS-потребителя у OpenCode-адресa
нет, и job'а под него не появляется.

**Почему.** Публикация в реестр — момент, когда обещание установки перестаёт
быть внутренним. Ни одна существующая проверка не доказывает, что реальный
клиент минимальной версии умеет поставить пакет и увидеть скиллы с сервером;
версия из checkout это не доказывает, потому что потребитель читает реестр.
Пол, а не потолок: 1.18.22 — самая старая поддерживаемая версия, новые
разрешены.

**Цена.** Два долгих job'а в теговом прогоне и зависимость дымовых проверок
от сетевого реестра npm. Симптомы «соскальзывания» адреса — версия не из
тега, `latest` вместо точной, checkout вместо реестра — закрываются проверкой
точной версии в команде установки и требованием публиковать до потребления.

**Что не меняется.** macOS-job'ы Codex и Claude Code нетронуты; режим
upstream без тега форка дымовых потребителей не запускает; агрегатный гейт
`unica-ci` лишь расширен двумя новыми потребителями.
