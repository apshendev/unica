# Domain Docs

How the engineering skills should consume this repo's domain documentation when exploring the codebase.

This repo already has a normative architecture registry (`arch/`). These rules adapt the standard
`CONTEXT.md` + `docs/adr/` layout onto it instead of creating a second decision system.

## Before exploring, read these

- **`arch/index.md`** — one line per symbol. Resolve any `DEC.*` / `INV.*` / `CTR.*` through it
  and open only the records you need.
- **`CONTEXT.md`** at the repo root — the live glossary, created lazily by `/domain-modeling`;
  may not exist yet.
- **`docs/design/**` and `docs/plans/**`** — dated history of how past changes were made. Read
  them only to reconstruct one specific change, never as a source of current rules.
- **`docs/arch-v1/`** — frozen pre-reset history, including its glossary; not normative.

If `CONTEXT.md` doesn't exist, **proceed silently**. Don't flag its absence; don't suggest
creating it upfront. The `/domain-modeling` skill (reached via `/grill-with-docs` and
`/improve-codebase-architecture`) creates it lazily when a term actually gets resolved.

## Layout

Single-context:

- Glossary: root `CONTEXT.md` — glossary only, no implementation details, no specs.
- Decisions: `arch/decisions/YYYY-MM-DD-<slug>.md` (`DEC.YYYY-MM-DD.<SLUG>`) — this repo's ADR
  equivalent.
- Checkable rules: `arch/invariants/` (`INV.*`) and `arch/contracts/` (`CTR.*`), each naming its
  owning `DEC.*` and its check.

Field schemas and record lifecycle rules live in `arch/README.md`; the registry index is
generated by `scripts/arch/registry.py`.

## Use the glossary's vocabulary

When your output names a domain concept (in an issue title, a refactor proposal, a hypothesis, a
test name), use the term as defined in `CONTEXT.md`. Watch this repo's overloaded terms: `host`
(host application vs OS target), `client` (MCP peer vs host-app consumer), `manifest` (six
different files), `package` (thin package vs runtime archive vs tool bundle vs Cargo package).

If the concept you need isn't in the glossary yet, that's a signal — either you're inventing
language the project doesn't use (reconsider) or there's a real gap (note it for
`/domain-modeling`).

## Flag decision conflicts

If your output contradicts an active registry record, surface it explicitly rather than silently
overriding:

> _Contradicts DEC.2026-08-22.LINEAR-PUBLICATION — but worth reopening because…_

Per `arch/README.md`, a product record is never rewritten in place: either propose the successor
record together with the change, or drop the approach.
