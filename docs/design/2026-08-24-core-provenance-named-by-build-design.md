# Core provenance is named by the build

## Задача

Задача #2 (fork `apshendev/unica`): происхождение ядра в порождаемом пакете
должно стать явно выбираемым, не меняя поведения upstream. Кандидат форка
называет `apshendev/unica` владельцем артефактов ядра и никогда молча не качает
ядро той же версии из upstream.

## Что мешает сегодня

Адрес ядра сегодня прибит с двух сторон провода:

- `scripts/ci/package-unica-plugin.py` пишет URL ядра из константы
  `SOURCE_REPOSITORY` и те же строки — в `source`/`release` манифеста;
- `crates/unica-bootstrap/src/manifest.rs` сверяет и идентичность, и префикс
  URL ядра против собственной константы.

`DEC.2026-08-20.ENGINES-COME-FROM-THE-TOOLCHAIN` закрепил правило «адресов
ровно два, третий — новая запись реестра». Эта записка и есть та новая запись:
происхождение ядра перестаёт быть единственной константой и становится входом
сборки с upstream-умолчанием.

## Решение

1. **Упаковщик** принимает явный вход `--core-release-repository`
   (умолчание — прежний upstream). Вход задаёт каждый адрес ассета ядра и
   поля `source.repository`/`release.repository` в `runtime-manifest.json`.
   Вызовы без входа порождают байт-в-байт прежний манифест.
2. **Bootstrap** принимает то же происхождение в момент сборки через
   `option_env!("UNICA_BOOTSTRAP_CORE_REPOSITORY")`; умолчание — тот же
   upstream-литерал. Валидация параметризована одобренным репозиторием ядра,
   поэтому сборка форка принимает манифест форка и отказывает манифесту
   upstream (и наоборот) — «никогда молча» доказано обеими сторонами.
3. **Сборка инструментов** (`scripts/ci/build-unica-tools.py`) передаёт вход в
   cargo-окружение; CI-сборка и локальный установщик получают его одним
   env-переменной, без дублирования флагов.
4. **Workflow** выводит репозиторий ядра из `github.repository`:
   `https://github.com/<owner>/<repo>`. На upstream это даёт прежнюю строку
   без изменения поведения; вилки получают самосогласованную поставку без
   литерального имени форка в workflow.
5. Происхождение тулчейна не выбирается: движки и дальше приезжают только из
   `IngvarConsulting/unica-toolchain`.

## Чем проверено

- `tests/ci/test_package_unica_plugin.py` — артефактные тесты: переопределение
  форка и умолчание upstream на полном прогоне упаковщика.
- `crates/unica-bootstrap/tests/manifest_contract.rs` — манифест форка принят
  сборкой, назвавшей форк; отказан умолчанием и наоборот.
- `tests/ci/test_product_contracts.py` — обе стороны провода выбирают одно
  умолчание одним механизмом; тулчейн-литерал остаётся единственным.
- `tests/ci/test_unica_workflow.py` — сборка передаёт репозиторий ядра
  упаковщику и bootstrap, выводя его из `github.repository`.

## Что не меняется

Публичная MCP-поверхность, `unica.*`, идентичность сервера, конвейер
публикации upstream, каталоги Codex/Claude и их проверки остаются как есть.
Каталог Claude продолжает адресовать upstream-marketplace: выбор происхождения
ядра — свойство выпуска, а не каталога.
